# Activity 2 — App icons, screenshots and store assets

Lab Exercise 06 · IT3060 · FitFlow 1.1.0

All assets live in [`store-assets/`](../../store-assets/README.md) and are **generated from code**:
icons and promotional graphics are drawn with Python/Pillow, and screenshots are captured from
the real app by an automated Flutter integration test. A change to the UI or brand is a re-run, not
a redesign. Every file is checked against the Google Play and App Store rules by
[`validate_assets.py`](../../store-assets/_tools/validate_assets.py); the result is in
[`evidence/asset-validation.md`](evidence/asset-validation.md).

## 1. Branding and icon design

The redesign's "Focus Flow" direction (Lab 03) is carried into the icon:

| Element | Meaning | Value |
|---|---|---|
| Indigo → violet gradient | Focus, calm | `#4338CA` → `#6D28D9` |
| Open ring | A session and its rest timer; the gap reads as motion ("flow") | White |
| Lightning bolt | Energy, today's workout | Coral `#FF6B4A` |

The same tokens are used in the app ([`lib/core/theme.dart`](../../frontend/mobile/lib/core/theme.dart)),
splash screens and store graphics, so the store listing, launcher and first screen look like one
product. The design deliberately avoids the green "heart + pulse" look common to health apps so
FitFlow stands out in Health & Fitness search results.

### Icon set

| Asset | Size / format | Where it is used | Rule applied |
|---|---|---|---|
| `ff_android_icon_512.png` | 512×512 PNG | Play Console hi-res icon | Full square; Google applies the mask |
| `ff_ios_appstore-icon_1024.png` | 1024×1024 PNG, **no alpha** | App Store Connect | Apple rejects transparency and pre-rounded corners |
| Adaptive icon (foreground, background) | 108 dp layers, all densities | Android 8+ launchers | Mark kept inside the 66 dp safe zone so circle, squircle and teardrop masks never clip it |
| Monochrome layer | Single-colour silhouette | Android 13+ themed icons | System tints it to match the wallpaper |
| iOS `AppIcon.appiconset` | 20–1024 pt, @1x–@3x | iPhone/iPad home screen, Settings, Spotlight | Generated by `flutter_launcher_icons`, alpha removed |
| Legacy `mipmap-*/ic_launcher.png` | mdpi–xxxhdpi | Android 7 launchers | Full-bleed version |

The icon was checked at real launcher size (48 px), where the ring and bolt stay distinct. The first
draft had a smaller bolt and misaligned rounded ends on the ring; both were corrected before export.

Splash screens were changed from Flutter's default white/logo to brand indigo on both platforms
(Android 12+ system splash, pre-12 `launch_background`, iOS `LaunchScreen.storyboard`) so start-up
moves straight into the indigo welcome screen without a flash of white.

## 2. Screenshots

### 2.1 How they are captured

[`integration_test/screenshots_test.dart`](../../frontend/mobile/integration_test/screenshots_test.dart)
launches the app with an empty store, captures the welcome screen, loads three weeks of fictional
demo history (profile "Amaya", sessions with progressive weights, today's meals, a circle post), then
navigates to each screen and captures it.
[`scripts/capture_screenshots.sh`](../../frontend/mobile/scripts/capture_screenshots.sh) runs that
test on every target device and orientation:

| Target | Device | Raw capture |
|---|---|---|
| Android phone | Pixel 9a emulator, Android 16 | 1080×2424 |
| Android 7-inch tablet | Emulator, 1920×1200 @ 320 dpi, portrait + landscape | 1200×1920 / 1920×1200 |
| Android 10-inch tablet | Pixel Tablet emulator, portrait + landscape | 1600×2560 / 2560×1600 |
| iPhone 6.9-inch | iPhone 18 Pro Max simulator, iOS 27 | 1320×2868 |
| iPad 13-inch | iPad Pro 13-inch (M5) simulator, iOS 27 | 2064×2752 |

[`frame_screenshots.py`](../../store-assets/_tools/frame_screenshots.py) then places each capture on a
brand background with a two-line caption and outputs it at the exact store size.

### 2.2 The screenshot story

Users decide mostly from the first two or three screenshots, so the order follows the redesign's
three headline promises before the supporting features.

| # | Screen | Caption | Requirement it demonstrates |
|---|---|---|---|
| 01 | Home | Today's workout, one tap away | R01 start with no setup, R14 quick log, U04 reasons on the card |
| 02 | Plan | Know why every exercise is there | R03–R05 planner inputs and adjustments, R15 "what it reads, where it runs" |
| 03 | Logger | Log a set with a single tap | R06/R07 pre-filled values, NFR1 one-tap logging, rest timer |
| 04 | Meal review | Snap your plate. Check. Save. | R08 camera first, R09/U08 per-item confidence and editable portions, ADR-003 on-device |
| 05 | Nutrition | Calories and macros at a glance | R08 day summary; local dishes |
| 06 | Circles | Share with your circle, not the world | R11 private by default, U01 audience label on every post |
| 07 | Progress | Progress in one clear sentence | R10 headline metric + sentence, R12 personal bests, R13 streak recovery |
| 08 | Privacy | Your data, your call | NFR5, export and erasure rights |

### 2.3 Output sizes

| Store slot | Output | Count |
|---|---|---|
| Play · phone | 1080×1920 (9:16) | 8 |
| Play · 7-inch tablet | 1200×1920 portrait, 1920×1200 landscape | 8 + 8 |
| Play · 10-inch tablet | 1600×2560 portrait, 2560×1600 landscape | 8 + 8 |
| App Store · iPhone 6.9-inch | 1320×2868 | 8 |
| App Store · iPad 13-inch | 2064×2752 | 8 |

The raw Pixel 9a capture is 2.24:1, which **Google Play rejects** (the long side may be at most twice
the short side). Framing each capture onto a 9:16 canvas fixes this and adds the caption in the same
step.

### 2.4 Problems found and fixed during capture

| Problem | Cause | Fix |
|---|---|---|
| Community audience label truncated ("Visible to 5 mem…") | Label shared a row with the like button and was ellipsised | Label given its own flexible space and allowed to wrap — this was the U01 privacy fix, so truncation defeated its purpose |
| Tablet layouts stretched cards across 2560 px | Phone layout reused unchanged | Page content capped at a centred 720 dp column on wide screens (`pagePadding`) |
| "Home" capture showed the welcome screen; meal photo missing | Android screenshot taken before the last frame was presented; image still decoding | Extra settle time before each capture; photo pre-decoded with `precacheImage` |
| Capture stalled overnight on the 10-inch tablet | Emulator screen slept and backgrounded the app | Script keeps the screen awake and dismisses the keyguard |
| iOS build failed: "resource fork, Finder information … not allowed" | Desktop folder synced by iCloud tagged build files | Build output moved outside the synced folder (see Activity 1 §3.3) |

## 3. Feature graphic, banners and video

| Asset | Size | Purpose |
|---|---|---|
| `ff_android_feature-graphic_1024x500.png` | 1024×500, no alpha | Play listing header. Key content kept away from the edges, where Play may crop or overlay a play button |
| `ff_promo_banner_1200x628.png` | 1200×628 | Social / website link preview |
| `ff_promo_square_1080x1080.png` | 1080×1080 | Social post |
| `ff_ios_iphone69_app-preview_886x1920.mp4` | 886×1920, H.264, 30 fps, stereo AAC (silent), ≈23 s | App Store app preview |
| `ff_promo_android-phone_1080x1920.mp4` | 1080×1920, H.264, 30 fps | Play promo video — Play takes a YouTube URL, so this file is uploaded to YouTube (unlisted) and the link pasted into the listing |

Apple requires app previews to be **real footage of the app**, 15–30 s long. The previews are screen
recordings of the simulator taken while the screenshot test drives the app, with a clean 9:41 status
bar. [`make_videos.sh`](../../store-assets/_tools/make_videos.sh) finds the end of the test runner's
black "Test starting…" screen automatically, cuts everything before it, and encodes to Apple's
format.

## 4. Store listing text

In [`store-assets/listing/`](../../store-assets/listing/):

| Field | Store | Limit | Used |
|---|---|---|---|
| Title / name | Both | 30 | 29 — "FitFlow: Workouts & Nutrition" |
| Short description | Play | 80 | 78 |
| Subtitle | App Store | 30 | 24 — "Workouts planned for you" |
| Promotional text | App Store | 170 | 144 |
| Keywords | App Store | 100 | 98, comma-separated, no spaces, app name not repeated |
| Full description | Both | 4000 | ≈2 360 |
| Category | Both | — | Health & Fitness (App Store secondary: Food & Drink) |

Content decisions:

- **No "AI" claim.** The prototype's planner is rule-based. Calling it "AI" would breach Apple
  guideline 2.3 (accurate metadata) and Google Play's misleading-claims policy, so the listing says
  "smart planner" and "explains itself". The architecture's ML service (ADR-001) can change this
  wording when it ships.
- **No unverified claims.** A draft line saying contrast was "checked against WCAG 2.1 AA" was removed
  because no contrast audit has been done yet; it now says "designed for accessibility".
- **Medical disclaimer** in the description, matching the in-app text.
- **Privacy URL** included in the description and the listing field.

## 5. Guideline compliance

[`evidence/asset-validation.md`](evidence/asset-validation.md) lists every check. In summary:

| Rule | Applies to | Status |
|---|---|---|
| Exact pixel sizes per slot | All images | Checked per file |
| No alpha channel | App Store icon, all screenshots, feature graphic | Checked per file |
| Long side ≤ 2× short side; 320–3840 px | Play screenshots | Checked per file |
| 2–8 screenshots per device type (Play), 1–10 (App Store) | Screenshot folders | Checked per folder |
| File size (Play icon ≤ 1 MB, screenshots ≤ 8 MB) | Play assets | Checked per file |
| Character limits | All listing text | Checked per field |
| No banned claims ("#1", "guaranteed", "clinically proven"…) | Descriptions | Checked per field |
| Keyword field hygiene | App Store keywords | Checked |
| Real app footage, 15–30 s, ≤ 30 fps, stereo audio | App preview | Verified with `ffprobe` |

Not automated, checked by hand: the screenshots show only fictional people and data; no other brand,
device frame artwork or third-party image appears; the meal photo is original artwork.
